Source: 15 `CleanShot` screenshots of Arc's Keyboard Shortcuts settings pane
(`docs/hotkeys/*.png`), captured 2026-07-09. Arc's settings UI groups every
shortcut under exactly two headings — **Customized Shortcuts** (this
particular installation's overrides) and **Default Shortcuts** (everything
still on Arc's built-in binding, alphabetized by action name). Those two
headings are reproduced below as the two tables, matching Arc's own section
names.

Symbols are spelled out as `Cmd`, `Shift`, `Opt`, `Ctrl`, joined with `+`.
Rows with no key combination assigned are marked `unassigned`.

## Atrium mapping notes

- **Space switching (Atrium: Opt+Tab)** — already covered. Cmd+1..9 goes
  to the favourite tiles, so `goToSpace*` ships unassigned. Arc's
  equivalent is the per-space "Go to space '<name>'" pattern (customizable,
  Cmd+1-4 in this profile) plus dedicated Next/Previous Space shortcuts
  (Cmd+L / Cmd+H, customized here). `nextSpace`/`previousSpace` cycling
  itself ships FOUR default combos: Opt+Tab (pair), Cmd+Opt+Arrow,
  Ctrl+Opt+Arrow, and Cmd+Shift+Arrow (direct user report - see
  "Text-editing chords are gated" below for why the last one was held back
  and how it is safe now).
- **Tab Switcher (Atrium: Ctrl+Tab / Ctrl+Shift+Tab)** — Arc M3 parity: Arc's
  Tab Switcher (Ctrl+Tab / Ctrl+Shift+Tab) now maps to Atrium's instant
  recency (MRU) tab cycle over the active space's last 5 activated tabs. Fixed
  (not rebindable) and reserved from `hotkeys.json`. Atrium also adds a
  WYSIWYG sidebar-order cycle on Cmd+Opt+Down/Up (rebindable `nextTab`/
  `previousTab`) with no direct Arc equivalent.
- **Sidebar toggle (Atrium: Cmd+S)** — exact match: Arc's default
  "Show/Hide Sidebar" is also Cmd+S.
- **Command bar (Atrium: Cmd+T)** — partial overlap only. Arc's Cmd+T is
  bound to "New Tab...", not a command bar; Arc's own "Open Command Bar"
  action has no key bound at all in this profile (unassigned in both the
  Customized and Default lists). Worth flagging: Atrium's Cmd+T diverges
  from Arc's Cmd+T semantics.
- **New window (Atrium: Cmd+N)** — exact match: Arc's default "New Window"
  is also Cmd+N.
- **Close tab (Atrium: Cmd+W)** — semantic mismatch: Arc's Cmd+W is bound to
  "Archive Tab" (moves the tab to an archive, not a plain close). Arc has no
  default "close single tab" binding distinct from archive; the closest
  related defaults are "Close Window" (Shift+Cmd+W) and "Clear Unpinned
  Tabs" (Shift+Cmd+K).
- **View Archive (Atrium Cmd+Shift+A)** — Arc's "View Archive" is
  unassigned by default; Atrium binds `openArchive` to Cmd+Shift+A, free of
  every other default and reachable without a bound key via the command
  bar's "Open Archived Tabs" row. Plain SwiftUI dispatch (`HotkeyAction.
  openArchive`), not a C++-owned native intercept - not in the "Configurable
  native hotkeys" table below.
- **Toggle Developer Mode (Atrium Ctrl+Opt+D)** — Arc's own
  default, taken as-is; free of every other default at both the Atrium and
  stock-Chromium key-equivalent layers. Flips chrome://extensions'
  developer-mode pref via the new `toggle_extensions_developer_mode` host
  op. Plain SwiftUI dispatch (`HotkeyAction.toggleDeveloperMode`), same
  posture as `openArchive` - not in the "Configurable native hotkeys" table
  below.
- **Go to Sidebar Item 1-8 / last (Atrium `goToSidebarItem1`-`8`/
  `goToSidebarItemLast`)** — Arc ships all nine unassigned; Atrium matches
  exactly, same posture as `createSpace`: no default combo, rebindable in
  Settings only. Position N counts the Nth VISIBLE tab row in
  `cycleTabInSidebarOrder`'s own WYSIWYG order (pinned when not collapsed,
  grouped member rows when expanded, then ungrouped) - group headers and
  collapsed-section members are skipped, favorites are excluded entirely
  (they render as tiles, never rows). "Last" always lands on the final
  visible row, whatever the count. An out-of-range position is a no-op -
  unlike cycling, an absolute jump never wraps. A cold target materializes
  on landing, like the other tile jumps. Plain SwiftUI dispatch
  (`SpacesViewModel.activateSidebarItem`), same posture as `openArchive` -
  not in the "Configurable native hotkeys" table below.
- **Split with next/previous tab, toggle orientation (Atrium
  Ctrl+Shift+Right/Left, Ctrl+Shift+\)** — repurposes Arc's "Add/Switch Split
  View" cluster (Ctrl+Shift+=/1-4/]/[), which Atrium does not adopt (see
  below). Splits the active tab with its next/previous sidebar-order
  neighbor (`SpacesViewModel.splitActiveTabWithAdjacentTab`) or flips the
  active split's orientation (`toggleSplitOrientation`). Plain SwiftUI
  dispatch, same posture as `closeSplitPane` - not in the "Configurable
  native hotkeys" table below.
- **Numbered split-view slots and "Separate Page from Split View" — out of
  scope**. Atrium's `SplitState` is one primary/
  secondary pair per slot, not N addressable views, so "Switch to Split View
  1-4" would be an architecture change, not a hotkey binding. "Separate Page
  from Split View" is semantically identical to the existing `closeSplitPane`
  (`breakSplit`) in a two-pane model, so it isn't a new action either.
- **New in Arc, not yet in Atrium** — everything else cataloged above,
  notably:
  - Screenshot/capture tools (Capture full page, portrait mode, region capture)
  - Little Arc / Easel / New Note / New ChatGPT Message quick-create actions
  - Sidebar folder expand/collapse, sidebar item reveal/rename
  - Archive management: "Archive Tab" and "Reset all tabs in this Space"
    still have no Atrium equivalent. "Clear Archive" exists (Settings >
    Workspaces) and "View Archive" is now Cmd+Shift+A (see mapping
    notes above).
  - Tab lifecycle (Pin/Unpin, Restore Last Closed Tab, Reset Tab to Original
    URL). "Clear Unpinned Tabs" is now `clearTabs` on the same Shift+Cmd+K.
  - Find/replace, zoom, history/downloads/library panel shortcuts
  - Developer tools (Inspect Elements, JavaScript Console, Network
    Inspector) - "Toggle Developer Mode" is now Ctrl+Opt+D (see
    mapping notes above)
  - Window/app chrome (Minimize, Hide Other Windows, Blank Window, New
    Incognito Window, Quit)

## Presets

The Inputs pane offers three presets. `hotkeys.json` records the NAME of the
chosen one and merges the user's own rows over that preset's table, so a later
change to a preset still reaches the profiles that picked it.

- **Arc** — the chord table this document records. Arc's default where the
  Default Shortcuts table names one, this profile's own binding where Arc
  ships the row unassigned (Next Space, Previous Space).
- **Atrium** — Atrium's shipped table, the default for every file written
  before presets existed. Starts from Arc and moves only the chords listed
  below.
- **Custom** — not a table. The pane reads Custom the moment one row differs
  from the named preset's chord, and reads the preset again once every such
  row is back. Switching away from Custom discards those rows, so the pane
  asks first.

An unassigned row in a preset is an EMPTY list, not a missing one. The native
map leaves an absent action on its compiled-in chord, so a missing row would
keep Cmd+T on the command bar under a preset that does not bind it.

### Where Atrium differs from Arc, and why

- **`openCommandBar` (Arc unassigned, Atrium Cmd+T)** — Arc leaves its own
  command bar unbound and spends Cmd+T on New Tab. The command bar is how
  Atrium opens a tab at all, so an unbound row removes the entry point rather
  than freeing a key.
- **`editCurrentURL` (Arc unassigned, Atrium Cmd+L)** — Cmd+L is the address
  bar across Chromium and macOS. Arc's catalogued profile spends it on Next
  Space instead.
- **`nextSpace` (Arc Cmd+L, Atrium Opt+Tab, Cmd+Opt+Right, Opt+Ctrl+Right,
  Cmd+Shift+Right)** — the same collision read from the other side. Cmd+L
  stays on the address bar, so space cycling takes chords no other surface
  claims.
- **`previousSpace` (Arc Cmd+H, Atrium Shift+Opt+Tab, Cmd+Opt+Left,
  Opt+Ctrl+Left, Cmd+Shift+Left)** — Cmd+H is macOS Hide Application. The
  system takes it before any app sees the key.
- **`nextTab` / `previousTab` (Arc Cmd+Shift+] / Cmd+Shift+[, Atrium adds
  Cmd+Opt+Down / Cmd+Opt+Up and Cmd+J / Cmd+K)** — Atrium keeps Arc's pair and
  adds the arrows, because its cycle walks the sidebar's own vertical order
  and the arrows match what the eye sees.
- **`goToSidebarItem1`-`8` and `goToSidebarItemLast` (Arc unassigned, Atrium
  Cmd+Opt+1 to Cmd+Opt+9)** — Arc's per-space chords are assigned by hand, one
  space at a time. Atrium gives the plain digits to spaces, so the sidebar
  jump needs a row of its own.
- **`openArchive` (Arc unassigned, Atrium Cmd+Shift+A)** — Arc reaches the
  archive through its command bar. Cmd+Shift+A is free of every other default
  at both the Atrium and the stock-Chromium layer.
- **`toggleOverview` (Arc unassigned, Atrium Cmd+Shift+O)** — Arc has no
  overview surface. Its own Cmd+Shift+O opens the Little Arc "Open In" menu,
  which Atrium does not have.
- **`reloadClearingCache` (Arc unassigned, Atrium Cmd+Opt+R)** — Safari's
  Reload Page From Origin, borrowed because no Chromium browser binds a chord
  to it. Arc's nearest row, Clear Cookies and Refresh, ships unbound.
- **`reloadClearingSiteData` (Arc unassigned, Atrium Cmd+Shift+Opt+R)** — the
  fourth rung of the same ladder. Arc has no equivalent row at all.
- **`toggleSplitOrientation` (Arc unassigned, Atrium Shift+Ctrl+\)** — Arc's
  split cluster addresses numbered views, which Atrium's one-pair split has no
  equivalent for. The orientation flip is what Atrium put on that cluster.
- **`toggleAiPanel` (Arc unassigned, Atrium Cmd+Shift+I)** — opens or closes
  the AI panel. Arc has no AI panel to match, so it ships unassigned there.

Every other action carries the same chord in both presets, `goToSpace1`-`9`,
`toggleSidebar`, `reload`, `hardReload`, `littleWindow`, `pinToggleTab`,
`closeSplitPane`, `toggleDeveloperMode`, `toggleDevBar` and `clearTabs`
included.
`createSpace` ships unassigned in both.

## Configurable native hotkeys (todo 17 follow-up, shipped)

The C++-owned intercepts are rebindable through the same `hotkeys.json` as the SwiftUI actions:

| Action id | Default | Rebound example |
|---|---|---|
| `openCommandBar` | `cmd+t` | `"openCommandBar": ["cmd+shift+k"]` |
| `toggleSidebar` | `cmd+s` | `"toggleSidebar": ["ctrl+s"]` |
| `nextTab` (Arc M3) | `cmd+opt+down` | `"nextTab": ["cmd+shift+]"]` |
| `previousTab` (Arc M3) | `cmd+opt+up` | `"previousTab": ["cmd+shift+["]` |
| `editCurrentURL` | `cmd+l` | `"editCurrentURL": ["cmd+shift+l"]` |

Rules:
- Native-action combos MUST contain `cmd` or `ctrl` (macOS only delivers those through the key-equivalent chain); others are dropped with a log, per-combo.
- Rebinding an action away from its stock combo releases the stock key: Cmd+T reverts to a plain about:blank tab, Cmd+S to the native Save Page, Cmd+L to Chromium's own `IDC_FOCUS_LOCATION`.
- `ctrl+tab` and `ctrl+shift+tab` are RESERVED (the Arc M3 recency cycle is a fixed chord matched before this map): binding any action to either is rejected by both `ParseCombo` (C++) and `ReservedHotkeys` (Swift settings UI).
- A bound native combo wins over web-page shortcuts, menu accelerators, and (future) extension commands - "most reserved". Menu items still work by mouse and keep displaying their stock equivalents.
- Changes apply on relaunch (no file watcher; the settings window will push live later).

## Text-editing chords are gated

A hotkey bound to a chord macOS uses for text editing does not fire while a text
surface has the keyboard - the key reaches the field instead. Applies to both
dispatch routes (SwiftUI `keyboardShortcut` and the C++ raw-NSEvent hook).

Gated chords - AppKit's `StandardKeyBinding` set, intersected with what Atrium
can bind:

| Chord | macOS meaning |
|---|---|
| `cmd+arrow`, `cmd+shift+arrow` | line/document movement, and extending the selection |
| `cmd+a` / `cmd+c` / `cmd+v` / `cmd+x` / `cmd+z` | select all, copy, paste, cut, undo |
| `cmd+shift+z` | redo |
| `ctrl+{a,b,d,e,f,h,k,n,o,p,t,v,y}` | emacs bindings |
| `ctrl+shift+{a,b,e,f,n,p}` | the movement ones, extending the selection |

Rules:
- Gating is a property of the CHORD, not the action - a rebind onto a gated chord
  is gated automatically, with no per-action setting.
- Exactly two shipped defaults are in the set:
  `nextSpace`'s Cmd+Shift+Right and `previousSpace`'s Cmd+Shift+Left (the
  direct user report "I'm not able to change to the next workspaces with
  cmd+shift+left/right"). Blocked until this task because Cmd+Shift+Arrow is
  also AppKit's "extend selection to start/end of line" chord; every other
  shipped default is still ungated, so every other binding's behavior is
  unchanged. `cmd+opt+arrow` (space cycling's other default) is deliberately
  NOT gated: AppKit binds `cmd+arrow` and `opt+arrow` separately, never the
  pair.
- Fails closed. If the focus signal is unavailable, stale, or the app and its
  dylib are a mismatched pair, a gated chord does not fire. Swallowing a
  keystroke meant for a text field is the worse failure.
- Ungated chords are never affected, including when the signal is degraded.
- Text surfaces covered: page fields (`<input>`, `<textarea>`, `contenteditable`),
  the command bar, and the sidebar's own URL/filter/rename fields.
- Known residual race: if a text field gains
  focus after SwiftUI's last render but before the next keydown, that one
  keystroke is still consumed by the disabled-but-not-yet-rerendered button
  rather than reaching the field - judged better than switching workspace
  mid-edit. Closing it needs a keyDown monitor ahead of `.disabled`, out of
  scope here.
